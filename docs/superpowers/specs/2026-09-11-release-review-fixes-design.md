# 问爻 0.2.0 发布复核修正设计

## 目标

在不重算旧版卦例、不改变现有排盘口径的前提下，修正 0.2.0 发布复核中发现的四处一致性问题：旧记录时区提示、节气来源描述、现场摇卦开始时间恢复，以及发布记录元数据。

## 范围

### 1. 旧版卦例提示

- 仅在“卦例记录”列表中，对 `timeZone.assumed === true` 的可写卦例卡片显示提示：
  “旧版记录未保存时区，现按北京时间显示；原排盘结果未重新计算。”
- 不重新计算或改写旧记录的 `chart` 快照。
- 当前版本生成、`assumed` 不为 `true` 的记录不显示该提示。
- 结果页不重复显示该提示。

### 2. 节气来源描述

- 精简版提示词中的排盘规则改为：
  “交节时刻采用内置离线节气表（由寿星万年历算法生成；2019–2028 与香港天文台公布值核对，误差不超过 1 分钟）”。
- 专业版结构化 JSON 的 `rules.solarTermSource` 使用相同事实口径。
- 不修改节气数据、四柱算法、版本号或排盘结果。

### 3. `castStartedAt` 恢复语义

- `castStartedAt` 表示本次现场摇卦最初开始推进流程的绝对时刻，只用于记录。
- 活动草稿恢复时保留已有 `castStartedAt`；旧草稿没有该字段时保持为空。
- `castAt` 仍在第六爻完成时更新，并且是唯一参与四柱排盘的时间。
- 恢复 `castStartedAt` 不改变得卦时刻和四柱结果。

### 4. 发布文档

- 将 `docs/implementation-status.md` 中 0.2.0 发布包的大小和 SHA-256 更新为当前 `release/release-summary.md` 记录。
- 保留“真机验收与最终上传尚未完成”的状态，直到实际完成。

## 数据流与组件边界

- `HistoryPage/HistoryCard` 只读取迁移层已经提供的 `timeZone.assumed`，不承担迁移或重算职责。
- 提示词文字与结构化规则分别由现有 formatter 和 structured 模块维护，但测试要求两者表达同一来源事实。
- `useCaseSession.restoreState` 从草稿恢复记录字段；排盘仍通过既有 `buildChart(rawValues, castAt, overrides)` 路径，不新增第二条排盘路径。

## 测试设计

按测试驱动顺序完成：

1. 历史页测试：迁移旧记录后显示时区假设提示；当前记录不显示。
2. 提示词测试：精简版文字与专业版 JSON 都包含真实来源和验证范围，且不再声称整张表直接取自香港天文台。
3. 现场摇卦恢复测试：带 `castStartedAt` 的活动草稿恢复并完成后，该字段保持原值；`castAt` 取第六爻完成时刻。
4. 回归门禁：默认、UTC、America/New_York 三组 `npm test`，以及 lint、build、Playwright 全部通过。

## 非目标

- 不重算旧版卦例。
- 不扩展节气数据验证年份。
- 不改动 ZIP 结构或重新验证平台上传格式。
- 不新增 `castStartedAt` 的用户界面展示。
- 不提升 schema、engine 或 prompt 版本。

## 验收条件

- 只有迁移旧记录在卦例列表出现明确提示，原快照保持不变。
- 提示词准确陈述算法来源及 2019–2028 的香港天文台核对范围。
- 中断恢复不会丢失已有 `castStartedAt`，且该字段不影响四柱。
- 实施文档的 0.2.0 发布元数据与发布摘要一致。
- 所有自动化门禁通过。

---

## 实施结论（2026-09-11 完成）

本设计的四处修正全部成立并已实施，实现记录见 `docs/implementation-status.md` 的「2026-09-11 发布复核修正」。实施时按复核意见额外放宽了两点范围：

1. **节气来源表述另有两处同类措辞**：`src/engines/calendar/solar-terms-data.ts` 表头的「数据来源：https://www.hko.gov.hk/...」与生成脚本 `scripts/generate-solar-terms.mjs` 中的同一行，都暗示数据取自天文台。两处一并改正为「本表由算法生成；天文台公布值仅作为核对基准」，并重新生成数据表（数据行逐字未变，仅表头变化）。这不是「修改节气数据」，与本节非目标不冲突。
2. **`PROMPT_VERSION` 提升到 2.1.1**（原非目标为不提升）：本次改的是写进提示词、供外部 AI 阅读的规则文案，若沿用 2.1.0，同一版本号会对应两段不同文字，削弱提示词快照的可追溯性。`schemaVersion` 与 `engineVersion` 未动。

另有两处措辞在实现中做了收紧：规则文案写作「2019–2028 年的十二节与香港天文台公布值核对」（核对对象是十二个「节」，不是全部二十四节气，数据表也只收录节）；节气表覆盖范围写明 1899–2100。

按要求本次**未重新打包**：`release/wenyao-xhs-0.2.0.zip` 与 `release/release-summary.md` 仍对应修正前的源码，上传前需重新构建并打包。
