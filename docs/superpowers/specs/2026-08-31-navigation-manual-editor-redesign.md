# 问爻导航与专业手动排盘重设计规格

## 1. 目标

本次改造将“问爻”从简单页面替换式导航升级为可返回、可恢复状态的移动端工具，并以 `D:\HexaAgent` 的手动排盘逻辑为业务基线，重建适合小红书小工具宽度的专业排盘编辑器。

核心目标：

1. 页面前进和返回符合移动端使用习惯，返回上一页时保留草稿、搜索条件与滚动位置。
2. 手动排盘采用“自动推导优先、人工校正兜底”，不要求用户逐项录入可计算字段。
3. 所有交互组件具备即时反馈，页面切换平滑且尊重减少动态效果设置。
4. 专业 AI 提示词同时包含可读排盘文本与结构化 JSON，减少字段漏读和错位。
5. 保持完全离线、无外部资源和小红书静态代码包兼容性。

## 2. 设计基线

### 2.1 模式

这是一次保留品牌的产品界面重设计，不改变“问爻”的名称、首页主要入口、历史卦例体系和离线定位。

### 2.2 视觉判断

页面面向实际使用六爻排盘的用户，使用克制、专业、可核对的产品语言。保留现有纸墨、朱砂和宋体标题，不照搬原项目的桌面对话外壳。

设计参数：

- `DESIGN_VARIANCE: 5`
- `MOTION_INTENSITY: 5`
- `VISUAL_DENSITY: 6`

### 2.3 设计系统约束

- 延续现有原生 CSS token，不引入第二套组件系统。
- 全应用只使用现有朱砂强调色。
- 卡片、输入框和按钮遵循统一圆角规则。
- 不引入外部字体、图片、图标 CDN 或运行时网络请求。
- 页面只动画 `transform` 和 `opacity`。
- 所有动效支持 `prefers-reduced-motion`。

## 3. 导航与返回

### 3.1 导航栈

应用不再只用单个 `route` 字符串替换页面。导航层维护页面栈，页面记录至少包含路由、来源和可恢复的页面状态。

- 首页进入现场摇卦、手动排盘或卦例记录时，将首页保留在栈底。
- 从卦例记录打开结果页，返回时恢复历史页的搜索条件和滚动位置。
- 从手动排盘生成结果后，返回时恢复完整手动排盘草稿。
- 结果页继续保留“返回首页”作为明确动作，但页面左上角的返回按钮始终执行返回上一页。
- 浏览器或容器的系统返回优先弹出应用内导航栈；只有位于首页时才交还宿主处理。

### 3.2 页面顶部栏

所有非首页页面使用统一顶部栏：

- 左侧：返回按钮。
- 中间：当前页面标题。
- 右侧：与当前页面相关的轻量状态，例如“草稿已保存”或“已自动排盘”。

### 3.3 页面过渡

- 前进：当前页轻微向左淡出，新页从右侧轻微进入。
- 返回：方向相反。
- 持续时间为 180-240ms。
- 不延迟点击后的状态更新。
- 减少动态效果模式下取消位移，仅保留即时切换或极短淡入。

## 4. 手动排盘信息架构

页面按以下顺序排列：

1. 统一顶部栏。
2. 问题信息：问题、类别、补充说明。
3. 卦名搜索与自动填充。
4. 起卦时间、四柱与空亡。
5. 六爻专业编辑器。
6. 本卦与变卦实时摘要。
7. 保存草稿与生成正式结果。

原界面的 `6/7/8/9` 不再作为用户可见输入。内部继续使用 `RawYaoValue` 保存数据，并按以下关系映射：

- 阴、动对应 6。
- 阳、静对应 7。
- 阴、静对应 8。
- 阳、动对应 9。

## 5. 卦名搜索与自动排盘

### 5.1 搜索

- 支持完整卦名和名称片段，例如“地天泰”或“泰”。
- 下拉结果展示匹配项数量、当前选中项和空结果状态。
- 键盘和触摸均可操作。
- 选择卦名后立即关闭结果并显示“已自动排盘”反馈。

### 5.2 自动推导

选择卦名或修改六爻阴阳后，系统自动完成：

- 本卦识别。
- 上下卦与卦宫。
- 纳甲干支。
- 地支与五行。
- 六亲。
- 世爻与应爻。
- 默认伏神。

标记动爻后，系统实时完成：

- 变卦识别。
- 变卦纳甲。
- 变卦地支、五行和六亲。
- 动爻位置更新。

填写起卦时间后，使用现有离线历法引擎自动生成四柱。填写或修改日柱后，系统自动更新：

- 六神。
- 旬空。
- 本卦和变卦逐爻旬空标记。

## 6. 六爻专业编辑器

### 6.1 排列与移动端布局

六爻从上爻排列到初爻。每爻在手机端使用两行紧凑布局：

- 第一行：爻位、六神、阴阳爻图形、动静、世应。
- 第二行：六亲、地支、伏神入口。

伏神展开后显示伏神六亲和伏神地支。动爻使用朱砂色强调。有动爻时在编辑器下方实时展示变卦名称与动爻摘要。

### 6.2 自动值与人工覆盖

六神、阴阳、动静、六亲、地支、世应和伏神均可人工校正，但自动值是默认来源。

- 人工修改的字段记录在 `overriddenFields`。
- 人工覆盖字段显示“已校正”状态。
- 每一爻支持恢复自动值。
- 专业编辑器提供“恢复全部自动值”，执行前需要二次确认。
- 修改会影响其他推导字段时，只重算未被人工覆盖的字段。

### 6.3 完整性校验

生成正式结果时检查最终结果，而不是要求用户手工填写：

- 问题不为空。
- 年柱、月柱、日柱、时柱完整。
- 六爻阴阳完整。
- 六爻地支与六亲完整。
- 六爻六神完整。
- 世爻恰好一个，应爻恰好一个，且不在同一爻。
- 某爻开始填写伏神后，伏神六亲和地支必须同时完整。

错误显示在对应区块或爻行下方，并将页面滚动到第一个错误。不得只使用笼统弹窗。

## 7. 互动反馈

每个可交互组件至少覆盖默认、按下、键盘聚焦和禁用状态；具备选中逻辑的组件还要覆盖选中状态。

- 按钮按下时轻微缩放或位移。
- 输入框聚焦时显示清晰边框和焦点环。
- 阴阳、动静、世应选中后立即更新填充色和辅助文本。
- 折叠项显示展开方向变化。
- 搜索显示匹配、无结果和选中反馈。
- 自动计算后显示短暂“已自动排盘”。
- 人工修改后显示“已校正”。
- 保存草稿、生成提示词和保存 AI 回答后提供就地成功反馈。
- 校验错误显示在字段附近。

## 8. 结果页

结果页按以下层级组织：

1. 问题、本卦、变卦、动爻与规则摘要。
2. 完整排盘，可展开逐爻详情。
3. 卦爻原文与白话参考。
4. AI 提示词生成。
5. AI 回答粘贴与保存。
6. 卦例标题、标签与后续验证。

人工覆盖字段在完整排盘中标记“人工校正”。卦爻原文与白话参考保持独立，不与结构化排盘数据混排。

## 9. AI 提示词

### 9.1 精简版

精简版包含：

- 问题、类别和备注。
- 起卦时间与四柱。
- 本卦、变卦和动爻。
- 世应关系。
- 建议用神。
- 关键排盘摘要。

精简版不附完整 JSON。

### 9.2 专业版

专业版由三层组成。

第一层为分析任务：要求外部 AI 选择用神、判断旺衰、分析世应、月建日辰、旬空、动爻和变卦，并在输出前执行字段自检。

第二层为人类可读排盘：沿用来源项目 `format_hexagram_text` 的表达方式，按上爻至初爻逐行列出六神、阴阳、动静、干支、五行、六亲、世应、旬空和伏神。

第三层为结构化 JSON，使用稳定字段：

- 问题、类别、备注、起卦时间和方式。
- 四柱、月建、日辰与旬空。
- 本卦、变卦、卦宫与动爻。
- 六爻逐项的阴阳、动静、干支、五行、六亲、六神、世应、旬空和伏神。
- 每爻人工覆盖字段。
- 提示词模板版本、排盘引擎版本和数据结构版本。

可读排盘与 JSON 必须来自同一个 `DivinationCase` 快照，避免两份数据不一致。

## 10. 状态与数据迁移

- 保持现有 `DivinationCase` 主结构和 IndexedDB 历史记录兼容。
- 扩展专业编辑状态时，不破坏旧卦例读取。
- 旧卦例缺少新增字段时使用迁移默认值，并保持只读降级策略。
- 导航栈只保存页面恢复所需的临时状态，不写入卦例数据库。
- 手动排盘草稿继续使用草稿存储，并增加搜索值、展开状态与人工覆盖信息。

## 11. 错误与恢复

- 自动推导失败时保留用户当前输入，并在相关区块显示具体错误。
- 存储失败时不清空表单，显示“尚未保存”状态并允许重试。
- 搜索无结果时不改变当前卦盘。
- 恢复自动值后重新运行完整排盘校验。
- 返回上一页不得隐式删除草稿。

## 12. 测试与验收

### 12.1 单元测试

- 阴阳与动静到 `RawYaoValue` 的映射。
- 卦名搜索和选择。
- 卦名或爻象变化后的纳甲、六亲、世应和伏神重算。
- 日柱变化后的六神和旬空重算。
- 人工覆盖字段保留和恢复。
- 专业提示词可读文本与 JSON 数据一致。

### 12.2 集成测试

- 手动排盘自动填充与人工校正完整流程。
- 校验错误定位到具体区块。
- 前进、返回、系统返回与页面状态恢复。
- 从历史页打开结果再返回，搜索条件不丢失。
- 从手动排盘进入结果再返回，草稿不丢失。

### 12.3 端到端测试

- 320px、375px 和 430px 无横向溢出。
- 搜索“地天泰”后自动生成完整本卦字段。
- 标记动爻后变卦实时更新。
- 自动四柱、六神、旬空与人工覆盖流程可用。
- 专业提示词包含可读排盘和合法 JSON。
- 离线重载后卦例、提示词和 AI 回答仍存在。
- 浏览器返回与页面返回按钮一致。

### 12.4 发布验证

- ESLint 通过。
- 全量 Vitest 通过。
- Playwright 通过。
- 小红书静态扫描 0 violations。
- ZIP 内路径只使用 `/`。
- ZIP 根目录直接包含 `index.html`。

## 13. 不在本次范围

- 内置在线 AI 调用。
- 自动向外部 AI 发送数据。
- 复制原项目的会话侧栏、知识库和推理链。
- 依赖后端 API 的四柱计算。
- 新增账号、云同步或跨设备数据同步。
