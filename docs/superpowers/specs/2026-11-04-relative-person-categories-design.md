# 问爻人物关系类别扩展设计

## 背景

当前问题类别只有事业、财运、感情、学业、健康、官司、出行、失物和其他。用户反馈在询问子女时没有合适类别，选择“其他”又无法给出有意义的候选用神。

六爻取用神并不存在一个可统一映射的“人物”类别。人物与问卦人的关系不同，主用神候选也不同；同一个人物还可能同时涉及健康、学业、婚恋或工作等事项。因此本次不新增笼统的“人物”，而是新增三个关系明确、可稳定映射的类别。

传统用神依据参考《增删卜易·用神章》与《卜筮正宗》：前者按亲属辈分分别归入父母、兄弟、子孙等六亲，后者也以所问人物和问卦人的关系决定用神。本设计只把这一关系路由用于候选提示，不把传统文本当作确定性预测依据。

- 《增删卜易·用神章》：https://zh.wikisource.org/zh-hans/增删卜易/8
- 《卜筮正宗》：https://ctext.org/wiki.pl?chapter=801184&if=gb

## 目标

1. 新增“子女／晚辈”“父母／长辈”“兄弟姐妹／同辈”三个问题类别。
2. 三个类别分别给出子孙、父母、兄弟作为主用神候选。
3. 明确类别表达的是所问人物与问卦人的关系，不把候选用神包装成无需确认的最终结论。
4. 复合问题继续保留完整问题原文，由外部 AI 结合具体事项判断辅助六亲。
5. 保持现有离线、无网络和可追溯提示词快照能力。

## 非目标

- 不新增笼统的“人物”类别。
- 不在本次增加第二个“所问事项”选择器。
- 不自动从自然语言识别人物关系。
- 不建立“人物关系 × 健康／学业／婚恋／工作”的穷举规则矩阵。
- 不把朋友、同事、陌生人强行归入兄弟类别；关系不明确时仍选“其他”。

## 方案比较

### 方案 A：三个独立关系类别（采用）

在现有单选类别中增加三个选项，分别映射一个主用神候选。优点是改动小、用户能直接理解、离线引擎和提示词都能复用现有数据链；缺点是复合事项仍需结合问题原文判断。

### 方案 B：人物类别 + 二级关系选择

先选“人物”，再选择子女、父母、兄弟等关系。语义完整，但会增加一步交互、数据字段和迁移成本；当前只有子女反馈，暂不采用。

### 方案 C：人物类别 + 从问题文本自动推断

由规则或 AI 从自然语言推断关系。离线环境下难以稳定覆盖称谓，且错误推断会直接选错用神；不采用。

## 用户界面

问题类别按以下名称展示：

- `children`：子女／晚辈
- `parents`：父母／长辈
- `siblings`：兄弟姐妹／同辈

三个选项排在“感情／婚姻”之后、“学业／考试”之前，使人物关系类相邻。类别选择区增加简短说明：

> 类别用于推荐主用神候选，具体仍需结合问题确认。

上述关系一律以问卦人为参照。例如询问自己的孩子选择“子女／晚辈”；询问朋友的孩子，若人物关系无法由现有类别准确表达，则选择“其他”并在问题或备注中说明。

## 用神候选与复合问题

新增映射：

| 类别 | 主用神候选 | 提示说明 |
| --- | --- | --- |
| 子女／晚辈 | 子孙 | 所问对象为问卦人的子女或晚辈，通常以子孙爻为主用神候选；若兼问健康、学业、婚恋或工作，需结合问题原文观察相关辅助六亲。 |
| 父母／长辈 | 父母 | 所问对象为问卦人的父母或长辈，通常以父母爻为主用神候选；若兼问健康、出行、财务或其他事项，需结合问题原文观察相关辅助六亲。 |
| 兄弟姐妹／同辈 | 兄弟 | 所问对象为问卦人的兄弟姐妹或同辈，通常以兄弟爻为主用神候选；若兼问健康、事业、婚恋或财务，需结合问题原文观察相关辅助六亲。 |

这里的“辅助六亲”只进入提示说明，不由本次离线引擎自动推断。这样可以避免把“孩子考试”机械地简化为只看子孙，也避免建立未经充分验证的组合规则。

## 提示词

精简版和专业版中的字段名称从“用神”收紧为“主用神候选”。专业版继续输出类别说明，外部 AI 输出约束继续要求先确认用神选择。

示例：

```text
类别：子女／晚辈
主用神候选：子孙
说明：所问对象为问卦人的子女或晚辈，通常以子孙爻为主用神候选；若兼问健康、学业、婚恋或工作，需结合问题原文观察相关辅助六亲。
```

结构化 JSON 保留原有 `category` 字段，值为稳定英文枚举；不新增自动推断结果字段。

## 离线初判

离线初判沿用现有 `YONGSHEN_BY_CATEGORY → buildContext → RULES` 数据链：

- 子女／晚辈只匹配本卦和伏神中的子孙。
- 父母／长辈只匹配本卦和伏神中的父母。
- 兄弟姐妹／同辈只匹配本卦和伏神中的兄弟。
- 世应、旺衰、旬空、月破、日破、动变和卦象结构规则保持不变。
- 结果仍是可解释的离线观察，不声称形成完整断卦结论。

## 数据兼容与版本

新增类别扩大了 `QuestionCategory` 的合法枚举集合，但不改变 `DivinationCase` 的字段形状。为保证已保存数据契约可追溯：

- `schemaVersion` 提升一版；迁移仅更新版本号，不修改旧记录的类别、排盘快照或提示词快照。
- `engineVersion` 提升一个补丁版本，记录新增的离线用神映射。
- `promptVersion` 提升一个次版本，记录“主用神候选”语义和新增类别说明。
- 应用包版本由实施时结合当前发布序列确定，不在本设计中硬编码。

旧记录迁移后保持原类别及全部快照；新类别记录由新版本正常读写。来自未来版本或迁移失败的记录仍按现有策略只读保留。

## 错误与边界处理

- 未选择类别时仍不能进入下一步。
- 非法类别值继续由领域校验拒绝。
- 关系不明确、朋友、同事、陌生人或代问关系复杂时选择“其他”，提示词要求外部 AI 先确认用神。
- 旧版活动草稿和手动排盘草稿恢复后保持原类别，不自动改成新增类别。
- 三个新类别统一追加复合风险提示：“如问题涉及健康、法律或财务事项，请咨询相应专业人士，卦象内容不能替代专业意见。”这样“父母健康”“兄弟纠纷”等问题不会因为选择人物关系类别而绕过高风险提醒；现有健康、官司和财务类别仍保留各自更具体的免责声明。

## 测试设计

1. 领域与迁移：三个枚举值通过校验；旧 schema 记录迁移后类别和快照不变；非法值仍失败。
2. UI：现场摇卦和手动排盘均展示三个新选项及候选用神说明，选中后可完成流程并保存。
3. 离线初判：三个类别分别只选择子孙、父母、兄弟；覆盖用神出现、伏藏和多现至少各一个确定案例。
4. 提示词：精简版和专业版使用“主用神候选”，输出正确类别标签和说明；结构化 JSON 保存稳定枚举值；提示词版本同步。
5. 风险提示：三个新类别均带复合健康／法律／财务提示，现有三个高风险类别的专项提示不退化。
6. 兼容：既有九类行为与断言保持不变，备份导出／恢复可往返三个新类别。
7. 全量门禁：默认、UTC、America/New_York 三组单元与集成测试，lint、build、Playwright 全部通过。

## 验收条件

- 用户可在现场摇卦和手动排盘中选择三个新类别。
- 保存、历史查看、搜索、备份恢复和提示词快照均保留正确类别。
- 三个类别分别以子孙、父母、兄弟作为主用神候选。
- 提示词明确这是候选，并提醒复合问题结合具体事项确认辅助六亲。
- 旧卦例不重算、不改类别、不改既有提示词快照。
- 所有自动化门禁通过。
